# RPC 节点与故障恢复

## 节点来源

五条内置主网各自提供 4 个不同运营方的 HTTPS 公共 RPC。应用启动先使用内置配置和本地缓存；随后在前台静默读取 TokenPocket 主目录（`ns=ethereum` 固定，只替换 `chain_id`）。如果某条链的主目录请求失败或返回空数据，再读取 Chainlist 作为该链的发现备选，不等待下载完成才打开钱包。目录地址和时间策略位于 `src/config/rpc.ts`。

目录只用于发现受支持网络的候选节点。`src/core/rpc-endpoints.ts` 对链与完整公开 URL 设有白名单，排除 API Key、凭据、私网地址和同运营方重复节点。添加运营方时需要一起更新白名单和对应测试。

刷新默认每 6 小时一次，失败后 15 分钟重试；缓存有效期为 7 天。离开前台会取消刷新，回来后在需要时继续。缓存损坏、目录下载失败或没有健康节点时保留已有配置。缓存只包含公开节点配置，单独保存，不包含钱包地址、私钥或助记词。

## 健康检查与读取

每轮最多探测 25 个候选节点、最多 3 个并行探测，单节点预算 6 秒、整轮预算 60 秒。检查链 ID、区块高度、最新区块时间、节点之间的高度差和响应速度，再为每链选择最多 5 个独立运营方。

钱包查询和 DApp 查询共用 RPC 池。自动模式下，慢读取可以切换备用节点，同一次查询最多竞争 2 个节点；节点失败后从 30 秒冷却开始，连续失败延长至最多 5 分钟，近期成功节点优先。竞争被取消不算节点失败。连接超时、HTTP/上游不可用、限流、服务过载等临时错误会使当前节点进入冷却并切换备用节点；合约执行错误（包括 revert、余额不足、nonce 冲突，以及带 `data` 的错误）保留原始结果，不作为网络故障重试。

手动选定节点后，查询、交易提交及提交后的状态确认都只使用选定节点。红色节点仍可被选中，其不可用状态会直接显示，不会自动改用其他绿色节点。需要恢复自动故障切换时，选择“自动选择”。节点选择不会改变列表顺序；切换后发起的读取不会复用上一个节点或自动池的待完成结果。

首页状态点按当前实际路由显示：自动模式汇总节点池，有正常节点则绿色，只有高延迟节点可用则黄色，全部已检测且不可用才红色；手动模式只显示所选节点。首页刷新最多并行探测 2 个公开节点，找到可用节点后停止追加探测；尚未检测的节点保留未知状态。

远端 RPC 仍是第三方服务。链 ID 和区块检查可以发现误配、停摆和明显落后，不能证明节点返回的每项数据正确，也不能保证节点在每个地区始终可访问。

## 交易广播

交易广播只向一个已验证网络的节点提交一次。广播响应丢失后，通过本地计算的交易哈希查询交易和回执；查到则使用原哈希继续追踪，无法确认则保留“结果待确认”状态和哈希，不把超时解释为发送失败，也不会自动换节点重复发送。

发送页面提供查询状态入口。待确认交易会记录到本地交易历史；DApp 相同请求在当前会话中重试时，优先检查之前的哈希。同一 DApp 同时提交相同交易时共享一次广播，每个请求仍独立通过审批、链与权限检查。查询暂时找不到交易也不代表该交易一定没有进入网络。

## 验证

运行 `npm run verify:rpc`，覆盖节点筛选、健康检查、缓存与前台调度、故障切换和交易广播边界。测试使用公开的离线数据，不访问用户钱包或真实广播交易。
